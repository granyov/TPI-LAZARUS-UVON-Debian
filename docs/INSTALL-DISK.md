# Готовый образ Debian 13 для TPI LAZARUS UVON

Образ ставится одной командой и при первом запуске доводит себя сам. Собирается
из образа предыдущего выпуска с обновлёнными пакетами и проверяется загрузкой на
плате — протокол последних испытаний:
[`TEST-REPORT-debian13-20261004.md`](TEST-REPORT-debian13-20261004.md).

## Что внутри

| | |
|---|---|
| Дистрибутив | Debian 13 (trixie), arm64, пакеты на дату сборки |
| Ядро | 6.12 из Debian, не вендорское |
| Device tree | `rk3568-tpi-lazarus.dtb`, собран из `os/rk3568-tpi-lazarus.dts` |
| Загрузчик | GRUB на ESP образа; ядро и initramfs — по ссылкам `/vmlinuz` и `/initrd.img` |
| Консоль | `ttyS2`, 1 500 000 8N1 — как у прошивки v3.9 |
| Размер образа | 4 ГиБ, корень занимает около 1 ГБ |
| Разметка | GPT: `p1` ESP 256 МБ (FAT32), `p2` корень (ext4) |

Работает вся периферия, которой плата пользуется: SATA, оба порта RGMII, обе
PCIe-карты Realtek на штатном `r8169`, OP-TEE, eMMC, microSD, RTC, термодатчики,
USB, оба FT4232H и оба порта V.24. Подробности — в `docs/BUILD.md`.

У портов постоянные имена, не зависящие от порядка, в котором ядро нашло
устройства:

| Что | Имя |
|---|---|
| RS-422/485 1–8 | `/dev/ttyRS485-1` … `/dev/ttyRS485-8` |
| V.24 1 и 2 | `/dev/ttyRS232-1`, `/dev/ttyRS232-2` (ядерные `ttyS0`, `ttyS1`) |
| Батарейные часы HYM8563 | `/dev/rtc-battery` |

Порты V.24 заработают после прошивки их мостов GD32F103 — см.
[`docs/V24.md`](V24.md).

Предустановлены `openssh-server`, `systemd-networkd` (DHCP на всех проводных
интерфейсах), `tailscale`, `device-tree-compiler`, `openocd` для прошивки
мостов V.24 и `picocom`. На последовательной консоли включён автоматический
вход под root.

## Чего в образе нет намеренно

Всё, что является секретом или привязано к конкретному экземпляру, вырезано и
создаётся заново при первом запуске:

- ключи хоста SSH — иначе все платы оказались бы с одинаковыми приватными ключами;
- состояние Tailscale вместе с ключом узла;
- `authorized_keys`;
- `machine-id`;
- привязка MAC к конкретной плате.

Поэтому **сразу после установки по сети войти нельзя** — сначала нужна консоль.

## Что требуется до установки

В eMMC должна быть прошита загрузочная цепочка TPI (U-Boot 2024.04 как UEFI),
версии **v3.9**. Образ содержит только ОС и GRUB; сам загрузчик платы он не
трогает. Исходники прошивки и установка на чистую плату — в репозитории
[TPI-LAZARUS-UVON-UEFI](https://github.com/granyov/TPI-LAZARUS-UVON-UEFI);
собранная v3.9 (`uboot.img`) лежит в комплекте eMMC этого выпуска, запись в
раздел `uboot` — [`docs/INSTALL-EMMC.md`](INSTALL-EMMC.md).

С прошивкой v3.7 образ тоже загрузится, но прошивка и GRUB говорят на 115200,
а ядро — на 1 500 000: терминал придётся переключить после строки
`EFI stub: Booting Linux Kernel`. Проще обновить прошивку.

## Установка

### С обычного компьютера

Самый простой путь, если диск можно подключить к ПК:

```sh
xz -dc tpi-lazarus-uvon-debian13.img.xz | sudo dd of=/dev/sdX bs=4M conv=fsync status=progress
```

`/dev/sdX` — диск целиком, не раздел. Проверьте `lsblk` дважды: команда стирает
всё содержимое.

Образ выкладывается в двух упаковках, распаковываются они в побайтно одинаковый
файл: `.img.xz` понимают графические писалки вроде Etcher и Raspberry Pi Imager,
а `.img.zst` распаковывается быстрее. Для `.zst` команда та же через `zstd -dc`.

### Не снимая диск: SATA как USB-диск

С прошивкой v3.9 SATA SSD платы виден компьютеру как USB-диск через порт
USB-C OTG: кнопка RECOVERY при включении → **USB mass storage: eMMC + SATA
SSD**. Дальше — та же команда `dd` на появившийся диск. Выход из режима — Ctrl+C
в консоли или «извлечь» на компьютере.

### Из другой системы на плате

Если на плате уже работает другая система на eMMC, образ пишется на SATA прямо
из неё:

```sh
xz -dc tpi-lazarus-uvon-debian13.img.xz | dd of=/dev/sda bs=4M conv=fsync status=progress
```

SATA загружается первым по умолчанию прошивки; если порядок меняли — кнопка
RECOVERY при включении → **Boot order: SATA SSD first**.

### С microSD

Записанная тем же способом карта грузится сама, если на SATA и eMMC
загрузочной системы нет: microSD третья в порядке загрузки v3.9. Чтобы
загрузиться с неё в обход порядка, держите RECOVERY при включении и выберите
**Boot service medium: microSD**. Из системы на карте образ переносится на SATA
так же, как из любой другой.

## Первый запуск

Занимает около минуты дольше обычного: служба `tpi-firstboot` делает следующее.

1. Создаёт ключи хоста SSH.
2. Создаёт `machine-id`.
3. Растягивает корневой раздел и файловую систему на весь носитель — образ
   собран под 4 ГиБ, а диск больше.
4. Задаёт MAC-адреса картам Realtek. Своего EEPROM у них нет; служба продолжает
   блок, который U-Boot выводит для встроенных портов из идентификатора
   кристалла, так что все четыре адреса платы оказываются связными:

   ```
   end0      …:d2   GMAC0 (fe2a0000), от U-Boot
   end1      …:d3   GMAC1 (fe010000), от U-Boot
   enP1p1s0  …:d4   задан
   enP2p1s0  …:d5   задан
   ```

   Адреса записываются в `/etc/systemd/network/20-tpi-realtek-*.link` и
   сразу применяются, так что уже первая загрузка идёт с постоянными адресами.

После этого служба больше не запускается.

## Первый вход

Только через последовательную консоль, **1 500 000 8N1** — по сети ключей ещё
нет. Прошивка, GRUB, ядро и приглашение входа говорят на одной скорости.

Вход под root происходит автоматически, пароля нет. Дальше обычным порядком:

```sh
mkdir -p /root/.ssh && chmod 700 /root/.ssh
cat >> /root/.ssh/authorized_keys <<'KEY'
ssh-ed25519 AAAA... ваш-ключ
KEY
chmod 600 /root/.ssh/authorized_keys
hostnamectl set-hostname имя-платы
```

Доступ к последовательному порту равносилен root. Если это неприемлемо, автовход
снимается удалением `/etc/systemd/system/serial-getty@ttyS2.service.d/autologin.conf`
— но тогда сначала задайте пароль root или ключ, иначе при отказе сети плата
станет недоступной.

Tailscale установлен, но не подключён:

```sh
tailscale up --hostname=имя-платы
```

## Обновление

Обычное `apt upgrade`. Новое ядро подхватывается само: GRUB берёт ядро и
initramfs по ссылкам `/vmlinuz` и `/initrd.img`, которые Debian переставляет при
установке ядра. Device tree от версии ядра не зависит и лежит отдельно —
`/boot/dtb/rk3568-tpi-lazarus.dtb`.

## Пересборка образа

Выпуск собирается одной командой на плате (или любой arm64-машине с Debian 13)
с правами root — из образа предыдущего выпуска:

```sh
scripts/build-debian-release.sh -d rk3568-tpi-lazarus.dtb -u uboot.img -m MiniLoaderAll.bin \
    tpi-lazarus-uvon-debian13.img /srv/выпуск
```

`uboot.img` (прошивка v3.9) и `MiniLoaderAll.bin` нужны только комплекту eMMC;
в репозитории их нет — в них заводские payload'ы TF-A и OP-TEE, — а взять их
можно из комплекта eMMC выпуска.

Что делается по шагам:

1. `update-debian-root.sh` — в chroot обновляет пакеты и ставит
   `util-linux-extra` (`hwclock` для батарейных часов), `openocd`, `picocom` и
   переданные `.deb`, если есть; старые ядра и исходники ядра удаляет;
2. `build-debian-image.sh` — размечает образ, копирует корень, вычищает секреты
   и кладёт файлы платы из `os/rootfs`: первую настройку, часы, имена портов,
   автовход на консоли; пишет `fstab` и меню GRUB;
3. `build-emmc-set.sh` — то же для комплекта eMMC, с прошивкой v3.9 (`-u`,
   `-m`) и таблицей разделов из `os/emmc`;
4. `build-update-img.py` — `update.img` для RKDevTool;
5. упаковка: `.img.xz`, `.img.zst`, `.tar.xz` комплекта и `SHA256SUMS-debian13`.

Корень создаётся без возможности ext4 `orphan_file`: её понимают только
e2fsprogs 1.47+, а более старые `e2fsck` и `tune2fs` (например, в Ubuntu 22.04)
отказываются работать с такой файловой системой.

Device tree собирается из `os/rk3568-tpi-lazarus.dts` по `docs/BUILD.md`;
сборка воспроизводима — тот же исходник даёт побайтно тот же DTB.
`build-debian-image.sh` умеет и прежний путь — снимок работающей системы
(`-s /`, по умолчанию).

## Проверка файла

```sh
sha256sum -c SHA256SUMS-debian13
zstd -t tpi-lazarus-uvon-debian13.img.zst
```
