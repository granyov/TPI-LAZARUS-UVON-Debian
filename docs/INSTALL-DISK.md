# Готовый образ Debian 13 для TPI LAZARUS UVON

Образ ставится одной командой и при первом запуске доводит себя сам. Собран из
системы, работающей на стенде, и проверен загрузкой на плате.

## Что внутри

| | |
|---|---|
| Дистрибутив | Debian 13 (trixie), arm64 |
| Ядро | 6.12 из Debian, не вендорское |
| Device tree | `rk3568-tpi-lazarus.dtb`, собран из `os/rk3568-tpi-lazarus.dts` |
| Загрузчик | GRUB на ESP образа, консоль `ttyS2` 115200 |
| Размер образа | 4 ГиБ, корень занимает около 1 ГБ |
| Разметка | GPT: `p1` ESP 256 МБ (FAT32), `p2` корень (ext4) |

Работает вся периферия, которой плата пользуется: SATA, оба порта RGMII, обе
PCIe-карты Realtek на штатном `r8169`, OP-TEE, eMMC, microSD, RTC, термодатчики,
USB и восемь `ttyUSB` от FT4232H. Подробности — в `docs/BUILD.md`.

Предустановлены `openssh-server`, `systemd-networkd` (DHCP на всех проводных
интерфейсах), `tailscale` и `device-tree-compiler`. На последовательной консоли
включён автоматический вход под root.

## Чего в образе нет намеренно

Всё, что является секретом или привязано к конкретному экземпляру, вырезано и
создаётся заново при первом запуске:

- ключи хоста SSH — иначе все платы оказались бы с одинаковыми приватными ключами;
- состояние Tailscale вместе с ключом узла;
- `authorized_keys`;
- `machine-id`;
- привязка MAC к конкретной плате.

Поэтому **сразу после установки по сети войти нельзя** — сначала нужна консоль.

## Что требуется до установки

В eMMC должна быть прошита загрузочная цепочка TPI (U-Boot 2024.04 как UEFI),
версии `v3.7` или новее. Образ содержит только ОС и GRUB; сам загрузчик платы
он не трогает. Установка прошивки — `docs/INSTALL.md` и `docs/EMMC-INSTALL.md`.

## Установка

### С обычного компьютера

Самый простой путь, если диск можно подключить к ПК:

```sh
xz -dc tpi-lazarus-uvon-debian13.img.xz | sudo dd of=/dev/sdX bs=4M conv=fsync status=progress
```

`/dev/sdX` — диск целиком, не раздел. Проверьте `lsblk` дважды: команда стирает
всё содержимое.

Формат `.img.xz` понимают графические писалки вроде Etcher и Raspberry Pi
Imager — распаковывать вручную не нужно, файл скармливается им как есть.

### С самой платы, через microSD

Если снимать диск неудобно, образ пишется на microSD, с неё поднимается система,
а уже из неё образ переносится на SATA.

Записать карту на любом компьютере той же командой, вставить в плату и прервать
автозагрузку по UART. Карту надо запустить вручную: `bootflow scan` её не
перебирает, потому что sdmmc2 в список загрузочных устройств U-Boot не входит.

```text
TPI-LAZARUS=> fatload mmc 2:1 0x10000000 EFI/BOOT/BOOTAA64.EFI
TPI-LAZARUS=> bootefi 0x10000000
```

Система поднимется с карты. Дальше с неё:

```sh
xz -dc /path/to/tpi-lazarus-uvon-debian13.img.xz | dd of=/dev/sda bs=4M conv=fsync status=progress
reboot
```

После этого карту надо **вынуть**. Вопреки тому, что можно решить по выводу
`bootflow scan` (карты там нет, потому что sdmmc2 не входит в список
загрузочных устройств), загрузка идёт не по этому списку: первым отрабатывает
менеджер `efi_mgr`, который перебирает носители сам и карту находит. С
оставленной картой плата будет грузиться с неё, а не с SATA.

## Первый запуск

Занимает около минуты дольше обычного: служба `tpi-firstboot` делает следующее.

1. Создаёт ключи хоста SSH.
2. Создаёт `machine-id`.
3. Растягивает корневой раздел и файловую систему на весь носитель — образ
   собран под 4 ГиБ, а диск обычно больше.
4. Задаёт MAC-адреса картам Realtek. Своего EEPROM у них нет, и ядро берёт
   случайный адрес при каждой загрузке; служба продолжает блок, который U-Boot
   выводит для встроенного порта из идентификатора кристалла, так что все
   четыре адреса платы оказываются связными:

   ```
   end0      …:d2   (U-Boot)
   end1      …:d3   (U-Boot)
   enP1p1s0  …:d4   (задан)
   enP2p1s0  …:d5   (задан)
   ```

После этого служба отключает себя и больше не запускается.

## Первый вход

Только через последовательную консоль, 115200 8N1 — по сети ключей ещё нет.
Вход под root происходит автоматически, пароля нет. Дальше обычным порядком:

```sh
mkdir -p /root/.ssh && chmod 700 /root/.ssh
cat >> /root/.ssh/authorized_keys <<'KEY'
ssh-ed25519 AAAA... ваш-ключ
KEY
chmod 600 /root/.ssh/authorized_keys
hostnamectl set-hostname имя-платы
```

Доступ к последовательному порту равносилен root. Если это неприемлемо, автовход
снимается удалением `/etc/systemd/system/serial-getty@ttyS2.service.d/autologin.conf`
— но тогда сначала задайте пароль root или ключ, иначе при отказе сети плата
станет недоступной.

Tailscale установлен, но не подключён:

```sh
tailscale up --hostname=имя-платы
```

## Пересборка образа

`scripts/build-debian-image.sh` собирает образ из работающей системы: размечает
файл, копирует корень, вычищает секреты, ставит GRUB и службу первого запуска.
Запускается на плате с правами root:

```sh
./build-debian-image.sh /путь/к/образу.img
```

Скрипт берёт `BOOTAA64.EFI` с рабочего ESP платы (`/dev/sda2`), поэтому
запускать его надо на системе, которая сама загружена этой цепочкой.

## Проверка файла

```sh
sha256sum -c SHA256SUMS
xz -t tpi-lazarus-uvon-debian13.img.xz
```
